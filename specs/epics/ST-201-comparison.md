# ST-201 renderer spike · comparison and evidence

**Status:** renderer selected by the owner on 2026-11-06; final art direction remains open. Reviewer: Codex, 2026-11-06. This isolated sample is not the full 40-space game and does not replace the current local UI.

## Sample and authority

[AC-39–40](../features/renderer-spike.feature) trace the comparison to `spikes/st-201/verify.js`. The [runnable sample](../../spikes/st-201/README.md) draws four synthetic spaces, two distinct tokens, dice, a sample property card and action treatment. The two boards share the same project-authored geometry and animation clock. The separate in-memory server calls the existing synthetic property-turn reducer with `[1, 1]`; it returns the accepted roll, revision and destination to both views. The client does not produce or commit outcomes. There are no real room credentials or saved matches in this server.

**Art direction:** warm cream, leaf green, terracotta and blue-green; rounded neighborhood shapes and lettered tokens; symbols and text alongside color. These shapes and page copy were created for this project. The sample is a direction to review, not a final 40-space visual design. The compact sample still uses comparison cards and explanatory text; the next game table must put the playable board and its active decision first.

## Results

| Check | Observed result | Limits |
| --- | --- | --- |
| Same server input | Both views show `[1, 1]`, Mai at the synthetic purchase space and the same HTML list; the server returns the same receipt for a duplicate ID and rejects a stale/conflicting revision. ## Build cost and implementation tradeoffs

Bun 1.4.4 minified the combined comparison to **1,416,604 bytes** (**391,157 bytes gzip**). To estimate contributions, rebuilding the same entry with Phaser external produced **189,523 bytes** (**60,015 bytes gzip**) for React/SVG plus shared application code; rebuilding with React and React DOM external produced **1,232,826 bytes** (**333,868 bytes gzip**) for Phaser plus shared application code. These are diagnostic bundles with unresolved externals, not independently shippable assets; they include shared code and are not production bundle budgets. Build outputs, minifier settings and versions affect these numbers.

Phaser supplies a game scene, graphics and Canvas/WebGL renderer selection, and would support richer scene composition; this spike deliberately uses a common animation clock, so it does not prove Phaser's animation advantage. Its bundle is materially larger in this sample and its canvas needs a maintained HTML equivalent. React/SVG makes individual vector elements inspectable in the DOM and is much smaller in this diagnostic build, but a complete scene, motion orchestration and effect system need additional design and testing. Both would add dependencies to the current zero-dependency application; this experiment isolates them under `spikes/st-201`.

**Decision:** the owner selected Phaser plus native HTML for the game. The accepted [ADR-007](../adr/ADR-007-renderer-proposal.md) records the tradeoffs. Check asset loading, accessibility, performance and maintainability against the full board and real devices in subsequent work; document any later architectural change.
